infra-ai-streaming

An open-source AI inference observability stack for the cardinality and event rates that break classic metrics pipelines. Same class of problem as hyperscale TSDB work — applied to LLM infrastructure.

Rust ingest→ Kafka→ Go consumer→ ClickHouse→ Grafana
Axum server, channel backpressure, per-tenant rate limits
Circuit breaker + Redis overflow + dead-letter path
Z-score latency anomalies per model (baseline v1)
Helm / HPA on consumer lag
WAL before Kafka for crash-safe ingest
Target: 1M events/min · sub-100ms ingest P99
Why infra-ai-streaming is shaped this way
01
Cardinality first. Inference events explode across model × tenant × phase; columnar analytics (ClickHouse) fits the query shape better than label-indexed TSDB paths.
02
Durability before Kafka. A WAL on the ingest tier closes the gap between HTTP accept and successful produce so crashes do not silently drop batches.
03
Isolation at the edge. Per-tenant token buckets in Rust with shared Redis state keep one noisy tenant from starving the pipeline.
04
Kafka as the spine. Rust ingest and Go consumers evolve independently while replay and lag metrics stay first-class operational signals.
