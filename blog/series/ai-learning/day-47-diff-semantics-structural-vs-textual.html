Day 47 — Diff Semantics — Structural vs Textual

Git diff for trees — stop at first changed tool output.

That's the whole idea behind today's pkg/diff package, and like most one-line design briefs it hides a real decision: diff can mean two very different operations depending on what you're comparing. Compare two text files and you get a textual diff — line by line, byte by byte. Compare two agent traces the same way and you get almost nothing useful, because the two traces were never going to be byte-identical even when they made the exact same decisions.

A Text Diff Assumes Two Files Are the Same Shape

Unix diff is one of the oldest, most reliable tools in software — it compares two files line by line and reports insertions, deletions, and changes. It works beautifully when "the same content" and "the same bytes" are the same claim, which is true for source code, config files, and most text.

An agent trace breaks that assumption immediately. Two runs of the identical prompt against the identical tools still carry different timestamp_ns values, different span_id UUIDs, and often differently-ordered JSON keys depending on which serializer produced each event. A textual diff of two such traces reports near-total disagreement on every single line, even when the model made the exact same tool calls in the exact same order both times.

So what: the moment "same decision" and "same bytes" stop being the same claim, a byte-level diff stops answering the question you actually have — and an agent trace hits that split on line one.

The DS Analogy — Two Witness Statements, One Interrogation Room

DS analogy — comparing accounts, not comparing transcripts
Two witnesses to the same event, interviewed separately, almost never use the same words. One says "the car sped off," the other says "the vehicle accelerated away quickly" — a word-for-word diff of their statements would flag nearly every sentence as different. An investigator doesn't read the transcripts that way. They extract the facts each statement claims — make, color, direction — and compare fact by fact, because the paraphrase never mattered and the first fact where the two accounts genuinely disagree is the only thing worth chasing.

That is the move pkg/diff makes on agent traces: extract the fact each step claims — which tool, with what input — and compare that, not the paraphrase sitting around it in the JSON payload.

So what: a structural diff isn't a smarter textual diff — it's a decision to compare a different, smaller thing entirely: the claim a step makes, not the prose it's written in.

The Composite Key Already Solved Half This Problem

Day 46 covered why pkg/mocker.ToolMocker keys its frozen responses on SHA-256(tool_name + ":" + input_hash) rather than the raw call: a composite key identifies which decision was made — call this tool, with this effective input — without carrying every byte of the request along with it. pkg/diff reuses that exact pair of fields as its unit of comparison.

for i := 0; i < min(len(callsA), len(callsB)); i++ {
    if callsA[i].ToolName != callsB[i].ToolName {
        return divergence(step: i+1, reason: "tool_name")
    }
    if callsA[i].InputHash != callsB[i].InputHash {
        return divergence(step: i+1, reason: "input_hash")
    }
}

Nothing about SpanID, Timestamp, or the raw Payload bytes enters the comparison at all. Two steps are defined as "the same decision" exactly when replay would serve them the identical frozen response — which is precisely what ToolName + InputHash already determines, since that's the lookup key ToolMocker.Respond uses.

So what: a good composite key pays for itself twice — the same field that let pkg/mocker serve deterministic replay in Day 44 is the field that makes structural diff cheap to write in Day 47, because "the unit that matters" was already decided.

Why ToolName Wins the Tie-Break

When both ToolName and InputHash differ at the same step, Compare reports tool_name as the reason, not input_hash — the check runs first and returns immediately. That ordering is a judgment call, not an arbitrary one: calling a different tool altogether is a more fundamental divergence than calling the same tool with different input, even though either fact alone already proves the traces disagree.

Two witnesses who disagree on both the getaway car's color and its direction of travel are not "twice as divergent" — the fact that they can't even agree on the vehicle is the one worth leading with. A different tool call subsumes a different input; reporting the input mismatch when the tool itself already changed buries the more useful fact under a less useful one.

So what: a diff algorithm's tie-break rule is itself a claim about which kind of disagreement is more informative — getting it backwards doesn't make the tool wrong, just less useful at the exact moment someone needs the answer fastest.

A Length Mismatch Is Still a Divergence

If every shared step matches but one trace ran three tool calls further than the other, that is not "the traces agreed on everything they had in common." A witness who stops their account three sentences before the other witness didn't corroborate those three sentences — they simply never spoke to them.

Compare treats the point where the shorter trace ends as the divergence, tagged missing_in_a or missing_in_b depending on which trace was longer. Reporting Found() == false here would hide a real behavioral difference: one run took an action — a retry, an extra lookup, a reroute — that the other run never took at all.

So what: "no divergence found" has to mean the traces actually matched everywhere they overlap and ran the same length — conflating "ran out of shared steps to compare" with "agreed" is the kind of bug that hides real regressions behind a green checkmark.

A textual diff tells you every byte that differs. A structural diff tells you the first decision that differs — which is almost always the only one you actually came to ask about.

Git diff for trees, applied to agent traces instead of directory structures, comes down to the same discipline as everything else this repo has built since Day 44: define the unit that actually matters — a tool call's name and effective input — and refuse to let noise in the surrounding bytes distract from it.

So what: the hardest part of writing a diff algorithm is rarely the walk-and-compare loop itself — it's deciding, up front, what two things have to be equal before you're willing to call them "the same," and that decision is where structural diff earns its keep over textual diff every time.
