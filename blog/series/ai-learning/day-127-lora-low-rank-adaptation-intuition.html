Day 127 — LoRA — Low-Rank Adaptation Intuition

A target_modules list in a trainer config reads like naming which layers to touch. It's actually a budget decision, and the rank next to it is the same move as compressed sensing — a low-dimensional approximation of an update that never needed the full-rank space it technically lives in.

target_modules=["q_proj", "k_proj", "v_proj", "o_proj"] in a trainer config reads like a list of which layers to touch during fine-tuning, and stops there for most people who copy it out of a tutorial. Writing this week's lora-trainer/DESIGN.md forced the next question: touch them how, and why does the list stop at four names instead of naming every linear layer in the model?

What the List Is Actually Selecting

A frozen pretrained weight matrix, W, doesn't move during LoRA fine-tuning. What moves is a separate update, ΔW, added to it at inference time — and LoRA's entire trick is refusing to store ΔW at full size. Instead it factors ΔW into two much smaller matrices, B and A, whose product approximates the update at a fraction of the parameters a full ΔW would cost.

target_modules is the list of which W matrices get this treatment. Every entry in it — q_proj, k_proj, v_proj, o_proj for attention, gate_proj/up_proj/down_proj for a Llama-shaped MLP block — is a separate frozen matrix that gets its own B·A side path. Leave a matrix off the list, and it stays exactly as pretrained, full stop.

So what: the list isn't naming "which parts of the model learn" in some vague sense — it's naming, one frozen matrix at a time, exactly where a low-rank side path gets attached, and everything left off the list is not being fine-tuned at all, no matter how central that layer is to the forward pass.

The Compressed Sensing Intuition

DS analogy — recovering a signal from far fewer numbers than it looks like it needs
Compressed sensing reconstructs a signal — an image, an audio clip — from far fewer measurements than the signal's raw dimension would seem to require, and it works because most real signals aren't actually using all of that dimension. A photo of a mostly-blue sky has millions of pixels but almost no information content across most of them; a handful of well-chosen measurements is enough to reconstruct it exactly, because the signal's true complexity lives in a small subspace of the space it's stored in. Rank-r LoRA makes the identical bet about a fine-tuning update: ΔW is stored as a full d×d matrix's worth of numbers, but the argument for LoRA is that the useful update — the direction fine-tuning actually needs to move the weights — occupies a rank far lower than d, so a rank-r approximation with r in the dozens recovers nearly all of it.

The parallel isn't decorative. Both techniques are betting that a signal which looks high-dimensional by construction is actually low-dimensional by content, and both fail the same way if that bet is wrong — too few measurements reconstructs a blurred photo, and too low a rank ships an adapter that can't represent the update the fine-tune actually needed.

Rank Is a Budget, Not a Quality Knob

It's tempting to treat rank the way you'd treat a learning rate — turn it up until quality stops improving. This week's design doc fixes a small grid instead: r∈{8,16,32,64}, with alpha pinned at 2r across every row, not a second free variable to search over.

That fixed ratio matters more than it looks. LoRA's actual update at inference time is scaled by alpha/r, so holding that ratio constant means a bigger rank buys more expressive capacity without also silently changing how strongly the adapter's output gets blended back in — rank and update magnitude move independently, on purpose.

147Mattn+MLP params, rank 16
2.0alpha/r, fixed across the grid

So what: a rank grid with a fixed alpha/r turns "how big should the adapter be" from an open search into a lookup against reserved training VRAM — the same "fix the field, don't build the search" move a first pass at a new module gets to make before any training script exists to search with.

The Arithmetic Rank Doesn't Show You

None of the numbers above account for the frozen base model itself, and that's the arithmetic a rank grid alone will never surface. A 70B base in 4-bit NF4, with double quantization on the block-wise scale constants, is roughly 36GB before a single adapter parameter exists — the floor every "reserved training VRAM" figure in this week's grid sits above, not instead of.

Double quantization is a second, smaller compression pass on top of NF4: the per-block scale constants NF4 needs are themselves quantized, saving roughly another 0.4 bits per parameter. At 70B parameters that's not a rounding error — it's close to 3.5GB, recovered by compressing the metadata a compression scheme needed to describe itself.

So what: a rank of 64 looks four times more expensive than a rank of 8 by parameter count alone, but both numbers are dwarfed by the ~36GB NF4 floor underneath them — which is why the design doc treats quantization arithmetic and the rank grid as one budget, not two separate decisions made by two different people at two different times.

The Generalizable Lesson

The specific numbers here are Llama-3-70B's. The transferable part generalizes to any low-rank adaptation of any large frozen model:

  1. A target_modules list is a per-matrix decision, not a per-layer or per-model one — a matrix left off the list is not fine-tuned at all, regardless of how central it is to the forward pass.
  2. Rank is a capacity bet, not a quality dial to maximize — the compressed-sensing framing (a high-dimensional signal that's actually low-rank in content) is the argument for why a small rank works at all, and it's a bet that can be wrong for a task far outside the base model's pretraining distribution.
  3. A VRAM budget built from a rank grid alone is incomplete without the frozen base model's own quantized footprint underneath it — the adapter is the part everyone sizes first, and the frozen weights are usually the part that actually decides whether the whole thing fits.

The tutorial version of target_modules is a copy-pasted list of four or seven strings. The version that survives writing a design doc against a real 70B model and a real GPU budget is a statement about which frozen matrices get a rank-r approximation, sized against a quantization floor that was never optional to account for.
